2. API REST (api.php)

2.1 Autenticación

La API usa autenticación opcional vía Bearer token. Se configura en api-config.php:

define('API_PASSWORD', 'tu-token-secreto-aqui');

Si no se define API_PASSWORD, todas las peticiones son públicas.

Peticiones autenticadas deben incluir:

// Header HTTP
Authorization: Bearer tu-token-secreto-aqui

// O parámetro GET
/api.php?action=users&token=tu-token-secreto-aqui

2.2 Endpoints Detallados

HEAD /api.php?action=ping

Propósito: Verificar disponibilidad del servidor.

Autenticación: No requerida.

Respuesta: HTTP 200 si el servidor responde.

GET /api.php?action=all

Propósito: Retorna todas las colecciones en un solo objeto JSON.

{
  "constants":      { ... },
  "locations_info": { ... },
  "stats":          [ ... ],
  "properties":     [ ... ],
  "empreendimentos":[ ... ],
  "faq":            [ ... ],
  "depoimentos":    [ ... ],
  "parceiros":      [ ... ],
  "team":           [ ... ],
  "blog":           [ ... ]
}

GET /api.php?action=[colección]

Propósito: Retorna una colección específica.

Colecciones válidas: properties, empreendimentos, blog, faq, depoimentos, parceiros, stats, team.

POST /api.php

Propósito: Guarda todas las colecciones.

Body: JSON con las colecciones a guardar.

{
  "constants":      { ... },
  "locations_info": { ... },
  "stats":          [ ... ],
  "properties":     [ ... ],
  "empreendimentos":[ ... ],
  "faq":            [ ... ],
  "depoimentos":    [ ... ],
  "parceiros":      [ ... ],
  "team":           [ ... ],
  "blog":           [ ... ]
}

Respuesta exitosa:

{ "ok": true, "message": "Dados salvos com sucesso!" }

Respuesta error:

{ "ok": false, "error": "mensaje del error" }

POST /api.php?action=login

Propósito: Autenticación de usuario.

// Request:
{ "username": "admin", "password": "admin123" }

// Response exitosa:
{ "ok": true, "token": "..." }

// Response error:
{ "ok": false, "error": "Credenciais inválidas" }

GET /api.php?action=setup

Propósito: Creación automática de tablas. Lee schema.sql del mismo directorio.

GET /api.php?action=users

Propósito: Listar usuarios registrados. Requiere autenticación.

3. DataProvider.js

Capa de abstracción que permite al frontend funcionar tanto en modo frontend (datos estáticos) como en modo API (base de datos).

3.1 Modos de operación

MétodoFrontend ModeAPI Mode
get(name)Retorna window[name] (síncrono)fetch GET a /api?action=name (Promise)
getAll()Objeto con todas las colecciones (síncrono)fetch GET a /api?action=all (Promise)
saveAll(data)Callback onFrontendfetch POST a /api (Promise)
ping()Promise.resolve(false)HEAD a /api?action=ping

3.2 Flujo de inicialización

  1. Al cargar la página, DataProvider lee localStorage.getItem('data_mode')
  2. Si es 'api', inicia modo API y hace ping automático
  3. Si el ping falla, vuelve a modo frontend automáticamente
  4. app.js verifica DataProvider.isApi() y carga datos si es necesario

4. Manejo de Errores en api.php

La API incluye manejadores globales de excepciones y errores:

// Todas las excepciones no capturadas retornan JSON
set_exception_handler(function($e) {
    http_response_code(500);
    echo json_encode(['ok' => false, 'error' => $e->getMessage()]);
});

7. Solución de Problemas Técnicos

ProblemaCausaSolución
Error 500 en api.php Credenciales de BD incorrectas, tabla no existe, o error SQL Verificar api-config.php. Ejecutar ?action=setup. Revisar logs de PHP.
"No active transaction" Rollback llamado sin transacción activa Quitar beginTransaction/commit del save handler (ya corregido en v1.0)
Datos no cargan del API Auth requerida para GET actions Agregar 'all' y GET actions a $skipAuth (ya corregido en v1.0)
window.DEPOIMENTOS undefined const no crea propiedad en window Usar nombres de variables directamente, no window[var] (ya corregido)
URL se acumula BASE_PATH vacío genera rutas relativas BASE_PATH debe terminar con '/' (ya corregido en v1.0)
Imágenes 403 Hotlinking en .htaccess Comentar reglas de hotlinking o agregar dominio actual a allowed referrers
saveFormsToData is not defined Función llamada antes de ser declarada Mover declaración de saveFormsToData antes de su uso en admin.js
Cache del navegador Archivos minificados cacheados Incrementar ?v=N en los script tags, o Ctrl+F5

8. Guía Rápida de Hostinger

  1. Subir archivos: Usa File Manager o FTP (FileZilla) para subir todos los archivos a public_html/
  2. Crear BD: En hPanel > Databases > MySQL Databases > crear base, usuario y contraseña
  3. Configurar: Copiar api-config.example.php a api-config.php y pegar credenciales
  4. Importar SQL: En phpMyAdmin, seleccionar la BD > Import > seleccionar schema.sql
  5. Verificar: Abrir https://tudominio.com/api.php?action=ping — debe responder OK
  6. Activar BD mode: Ir al sitio con ?edit=1 > Config > Activar modo BD > URL: /api.php
  7. Probar: Editar algo > 💾 Salvar (BD) > recargar página
⚠️ Nota importante: Hostinger puede tener restricciones de seguridad. Si encuentras errores 403 en imágenes, contacta al soporte de Hostinger o desactiva la protección hotlinking en el panel de control.

9. Mantenimiento

  • Backup de BD: Exportar regularmente desde phpMyAdmin
  • Actualizaciones: Mantener PHP actualizado (Hostinger lo gestiona)
  • Minificación: Después de editar app.js o admin.js, regenerar .min.js con terser
  • Cache: Incrementar ?v=N en index.html después de cambios
  • Logs: Revisar logs de error de PHP si hay problemas (Hostinger > Advanced > Error Logs)
